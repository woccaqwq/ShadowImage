# 程序实现任务清单

依据：[执行方案策划书.docx](执行方案策划书.docx)。

首轮 Demo 范围为新手教程、第一章第一关和第二关，需支持独立测试及连续游玩。程序侧主要负责模块二、三、六、八，并承担配置读取、资源接入、工程集成和测试修复。

策划书约定由两名程序共同承担。本文是程序团队的完整任务清单，个人分工需内部确定；勾选框用于后续跟踪，尚未根据现有代码核验完成度。建议方案及未定参数在文末单独列出。

## 1. 总体架构与公共接口

对应模块八，建议首先完成。

- [ ] 统一坐标、单位、画框参照、操作平面、旋转轴和模型旋转中心。
- [ ] 定义关卡数据：关卡 ID、部件、初始姿态、槽位、目标姿态、必需标记、互换组、等价朝向、容差、操作平面、画框、光源、目标图、完成图、教学步骤和推进去向。
- [ ] 明确状态归属：交互模块管理抓取，判定模块管理槽位，流程模块管理输入许可和关卡推进。
- [ ] 定义放置结果：自由放置、吸附、越界返回。
- [ ] 定义调用、事件及回执：选取、抓取、候选变化、释放槽位、吸附到位、重置、通关和演出结束。
- [ ] 区分槽位的空闲、临时保留、正式归位状态。
- [ ] 防止重复通知和旧回调生效，覆盖重置、换关、返回标题后的迟到回执。
- [ ] 约定模块依赖、资源接入规范及接口变更流程。
- [ ] 交付架构关系图、关卡数据表、接口清单和最小接入示例。

## 2. 玩家控制与物体交互

对应模块二，验收依据 M2-01～M2-08 及模块一相关规则。

- [ ] WASD 按镜头水平方向移动，鼠标控制观察。
- [ ] F 切换第一、第三人称；接入角色显隐，避免第一人称头部遮挡。
- [ ] 准星选取最前方可见的可交互部件，同时最多选中一个。
- [ ] 左键抓取，再次左键放置；点击空墙不产生抓取。
- [ ] 抓取时记录原姿态、原槽位和抓取偏移，避免物体瞬间跳动。
- [ ] 在关卡指定的操作平面拖拽，保持固定深度及原抓取对象。
- [ ] 实现持物时的移动和转镜控制，按最终确认规则执行。
- [ ] Q/E 和滚轮控制旋转，速度与步长可配置，两种视角下输入方向一致。
- [ ] 持物切换视角后重建拖拽参照，保证物体不跳、对象不变。
- [ ] 根据判定结果执行自由放置、吸附修正或越界返回。
- [ ] 吸附完成只发送一次到位回执，连续点击不能重复执行。
- [ ] 已归位物体可取回，抓取成功即通知判定模块释放旧槽位。
- [ ] 越界撤销时恢复抓取前姿态及原槽位占用。
- [ ] 重置、退出时取消抓取及未完成吸附；演出期间遵守输入许可。
- [ ] 交付教程与两关共用的玩家及可交互几何体组件。

## 3. 实时投影与解谜判定

对应模块三，验收依据 M3-01～M3-08。

- [ ] 在画框内固定显示目标剪影，并能与实际投影区分。
- [ ] 实时呈现部件移动、旋转和遮挡形成的组合投影。
- [ ] 同关固定解谜光源，换关读取新配置；移动玩家或切换视角不能改变墙上投影。
- [ ] 按整个投影外轮廓判断合法性：完全在框内、恰好贴边合法，部分出框非法。
- [ ] 放置时先检查越界，再检查吸附。
- [ ] 匹配类型、互换组、空闲槽位、平面距离和角度容差，容差包含边界。
- [ ] 支持对称等价朝向；球体可忽略朝向，非对称部件保留方向要求。
- [ ] 多候选只返回一个；预览与放置采用相同规则，点击时重新判定。
- [ ] 预览不占位；确认放置后保留槽位，到位回执后才登记正式归位。
- [ ] 保证一个槽位最多对应一个部件，一个部件一次只占一个槽位。
- [ ] 处理取回释放、越界恢复、取消及整关重置。
- [ ] 所有必需槽位正式归位且最后一次修正完成后，只发送一次通关通知。
- [ ] 重置清空候选、临时保留、正式占用和完成标记。
- [ ] 换关后仅接受本关本次操作的回执，忽略旧回执。
- [ ] 提供调试显示：部件、候选槽位、位置/角度误差、槽位状态、归位数量和通关通知次数。

**通关依据是槽位归位状态，不是剪影图片相似度。首轮 Demo 无需额外开发图像相似度识别系统。**

## 4. 界面、教学与完整流程

对应模块六，验收依据 M6-01～M6-08、M1-11～M1-15。

- [ ] 标题界面提供开始、退出；连续点击开始不能重复加载。
- [ ] 实现教程 → 第一章第一关 → 第二关 → Demo 结束的流程。
- [ ] 提供三个内容段的独立测试入口。
- [ ] 载入本关部件、槽位、目标、光源和教学配置，各模块初始化完成后才开放输入。
- [ ] 切关时清除上一关提示、抓取引用及状态。
- [ ] 按玩家实际有效操作推进教程，停留或无关操作不跳步骤。
- [ ] 接入移动、瞄准、抓取、拖动、放置、旋转、F 切换和长按 R 提示。
- [ ] 保证两种视角下提示可读，不遮挡关键谜题内容。
- [ ] F 切换与 R 重置不作为通关前置条件，允许直接解题。
- [ ] 长按 R 整关重置，一次长按只触发一次，恢复本关适用提示及反馈。
- [ ] Esc 返回标题，取消本关操作、提示、演出及回调；再次开始进入全新教程。
- [ ] 首次通关时锁定物体编辑和整关重置，只触发一次揭晓。
- [ ] 演出结束后显示继续，由玩家确认推进，防止双击跳关。
- [ ] 末关确认后进入结束界面，支持返回标题和重新游玩。
- [ ] 保留无限调整与重试，不增加超时失败、扣分或次数限制。

## 5. 关卡、美术与视听接入

配合模块四、五、七，相关验收依据 M4、M5、M7。

- [ ] 实现关卡配置读取，支持通过数据复用三个内容段的玩法。
- [ ] 与关卡负责人核对目标剪影、槽位和完成图来自同一参考解。
- [ ] 核对必要配置字段、槽位允许部件和资源引用，能还原关卡初态。
- [ ] 配置可交互预制体的碰撞体、选取层、描边对象和旋转中心。
- [ ] 统一画框可见内沿、合法区域和目标图范围。
- [ ] 接入选取、持物、吸附预览、归位、越界及重置反馈。
- [ ] 正式归位后才播放一次单件反馈，非末件归位时整体仍保持黑白。
- [ ] 越界返回原槽位时恢复归位外观，整关重置时清除局部反馈。
- [ ] 接入投影缝合、显色及胶片音效等揭晓演出，并提供一次结束回执。
- [ ] 揭晓后保留完成画面，等待玩家继续时不重复播放。
- [ ] 管理音乐、音效的播放、停止及循环，避免换关后叠加。
- [ ] 退出、换关时清理旧动画、音效、事件订阅和延时回调。
- [ ] 保证静音时仍能通过可见反馈区分预览、归位和通关。
- [ ] 正式模型替换后配合复测选取、旋转、投影、槽位和可解性。
- [ ] 核对资源清单中的关卡归属、触发/停止条件、循环设置和演出时长。

模型、图像、音乐音效和教学内容由对应成员提供，程序负责运行逻辑及资源接入。若具体视觉效果需要 Shader 或程序动画，应另行明确分工。

## 6. 工程集成、测试与交付

对应模块九、十，贯穿开发过程。

- [ ] 统一 Unity 版本、工程设置、目录命名和 GitHub 协作约定。
- [ ] 明确场景、预制体编辑责任，持续合并并产出阶段构建。
- [ ] 确保其他成员取得工程后可以复现打开和运行。
- [ ] 按规则编号记录版本、关卡、视角、实测结果和缺陷编号。
- [ ] 验证双视角操作及持物切换时的姿态稳定性。
- [ ] 验证框内、贴边、越界和越界恢复原槽位。
- [ ] 验证位置/角度容差边界、互换组、等价朝向和错误类型。
- [ ] 验证多候选稳定性、重复占位和取回后的再次吸附。
- [ ] 验证吸附中重置、迟到回执、重复通关及演出中退出。
- [ ] 验证长按 R 只触发一次、快速双击继续只推进一关。
- [ ] 验证三段独立可玩，以及标题到结束的连续流程。
- [ ] 验证超过 5 分钟仍能继续操作并完成，无失败惩罚。
- [ ] 在打包版本验证输入、退出、资源引用及完整视听播放。
- [ ] 修复自身功能和接口缺陷，按同一规则回归。
- [ ] 配合交付测试记录、问题记录、运行说明及演示录制材料。

## 7. 需要统一的设计细节

以下项目不应在实现时被当作已经确定的正式参数。

| 项目 | 策划书当前状态 | 需要落实的内容 |
| --- | --- | --- |
| 持物时暂停人物移动和转镜 | 建议方案 | 确认后统一两种视角行为 |
| Q/E、滚轮旋转轴 | 建议绕画框竖轴、横轴 | 确认旋转方向及中心 |
| 多候选选择 | 建议最近距离优先，等距按固定配置顺序 | 确认并共用同一判定逻辑 |
| 位置与角度容差 | 正式数值需试玩确定 | 按关卡配置；0.20 单位和 15°仅为测试示例 |
| 长按 R 时长 | 未指定 | 确定阈值和触发反馈 |
| 旋转速度、滚轮步长、吸附时长 | 未给出正式数值 | 配置化并通过试玩调整 |
| 三段关卡的部件及目标图案 | 教学结构已有建议 | 参考解验证后定稿 |
| 两名程序的职责分工 | 未细分到个人 | 明确各模块负责人、接口双方及集成责任 |

## 8. 建议实施顺序

1. **公共接口与测试关**：统一数据、状态和事件，搭建至少两个必需槽位的测试关。
2. **交互与判定原型**：跑通抓取、拖拽、旋转、投影、合法放置、吸附、取回和重置。
3. **三段流程**：接入教程和两关配置，完成标题、教学、通关、下一关及结束流程。
4. **正式资源与反馈**：替换模型，接入高亮、音效、显色演出，并复核参考解。
5. **打包验收**：完成独立与连续游玩测试，修复问题并交付 Demo。

也可以逐关完成全部功能，但三段内容共用操作、投影和判定。优先完成可复用核心，有利于两名程序分工接入，也能更早暴露吸附、重置和回执之间的问题。工程集成从开发开始持续进行，测试从首个可玩版本开始。
